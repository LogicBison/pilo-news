## `@<skill> <args>` = framework skill, not a Qwen Code skill

This repo is an Agent OS **thin-client consumer**: there is no local `.ai/`. Invocations like `@session-control start`, `@code-implementation plan`, `@ui-session close`, `@biz-director - …` are markdown-defined framework skills.

- They are **not** in your `skill` tool's list. Never call `skill: "session-control"` — no such skill is registered. Read the doc and follow it.
- Resolve `<source root>/skills/<name without @>/skill.md`. Also read `reference.md` in the same folder when `skill.md` links it — `session-control` keeps its close/commit protocol there.
- Everything after the skill name is the invocation: a verb plus modifiers (`start`, `status`, `context`, `close`, `close commit push`, `plan`, `complete`) or `- <free text>` for the directors. Parse it with the skill's own **Parse invocation** table; do not infer git behaviour from the verb alone.

## Verify — inside the containers, never on the host

Compose-based stack; one parameter `ENV ∈ {dev, prd}` selects `docker-compose.<env>.yml`, `apps/*/Dockerfile.<env>`, `.env.<env>`. Never run bare `npm/pnpm/pip/pytest/python/ruff` on the host.

```bash
./bin/start.sh --env dev up        # build + start (also: down, status, logs, shell, test, migrate, preflight, hosts)
./bin/start.sh --env dev test      # lint + type + tests in the containers
docker compose --env-file .env.dev -f docker-compose.dev.yml exec api bash -c "cd /app && pytest -q"
docker compose --env-file .env.dev -f docker-compose.dev.yml exec web bash -c "cd /app && pnpm lint && pnpm exec tsc --noEmit"
```

`api` → `apps/api` (`/app`): `pytest -q`, `ruff check . && ruff format --check .`, `mypy src`; schema changes are numbered idempotent SQL under `apps/api/migrations` via `@db-migration`. `web` → `apps/web` (`/app`): `pnpm lint`, `pnpm exec tsc --noEmit`, `pnpm test`, `pnpm exec playwright test`. One-off scripts go in `apps/api/scripts`. Stack detail: `DOCS_TECH_STACK.md`, `DOCS_UI_STACK.md`.

## Non-negotiables (full text in `.cursorrules`)

- **Same-message approval only**, never standing: `git commit` / `git push`, deleting files, `DROP`/`TRUNCATE`/volume wipes (`destroy`, `down -v`), history rewrites, and edits to `.work/PROTECTED_SURFACES.json` paths (compose files, Dockerfiles, `apps/web/next.config.ts`, `tsconfig.json`, `package.json`, `postcss.config.mjs`, `.env*`). Plain `@session-control close` with a dirty tree is a valid pass — hand over the draft message and `git add` scope; the operator commits.
- **Commits:** `REF: subject` when a ref is known (`.work/active-ref`, branch, HANDOFF, last commit), else `type: description`. No "Generated by"/agent signature, no dates-as-signature. No `Co-authored-by:` trailer — hooks strip and reject it.
- **Evidence over memory:** report actual command output; never claim fixed/passing/implemented without it. State what you checked and what is unverified.
- **Output economy:** chat prose ≤150 words (code, diffs, command output and the handoff sections excluded); ask before exceeding it or widening scope. Close each turn per the Operator handoff contract in `<source root>/skills/SKILL_DEPENDENCIES.md`.
