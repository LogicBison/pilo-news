# CTA and lead-capture component brief

**What it is:** design intent for the lead CTA and form components: hierarchy, placements, states, copy rules, a11y, and analytics hooks.
**Status:** Draft (2026-11-05) · **Needs:** UI foundation (`@ui-design-foundation`) before component promotion; owner review of placements.
**Related:** `.work.biz/strategy/lead-generation.md`, `.work/standards/20261105-cta-lead-capture.md`.

---

## 1. Components

| Component | Purpose | Variants |
|-----------|---------|----------|
| `CtaCard` | Primary conversion block (hero, end-of-article, search) | `hero`, `inline`, `compact` |
| `CtaButton` | Button/link trigger | `primary`, `secondary`, `quiet` |
| `LeadForm` | Short form | `consultation`, `brief` |
| `StickyCta` | Mobile bottom bar | consultation only |
| `TrustLine` | Disclosure + response expectation | per channel |
| `ConsentField` | Explicit opt-in | consultation, brief |

## 2. Hierarchy

1. One primary CTA per page; no competing primary buttons.
2. CTA card uses the channel accent token, not a new colour.
3. Headline ≤ 8 words; supporting line ≤ 20 words; button label ≤ 4 words.
4. Never place the CTA inside the reading column between paragraphs; use after-summary or end-of-article slots.
5. Mobile: sticky bar appears after 60% scroll, dismissible, never covers content permanently.

## 3. Copy rules (labels)

| Slot | Rule | Example |
|------|------|---------|
| Headline | verb-first, concrete, no hype | "Talk to a specialist" |
| Support | what happens next + timing | "A partner in your area replies within one business day." |
| Button | verb + object, sentence case | "Request a consultation" |
| Consent | plain, specific, unchecked | "I agree to be contacted about this request." |
| Error | what to fix, no blame | "Enter a valid email address." |

Banned: "act now", "limited", "guaranteed", "risk-free", "unlock", "exclusive", exclamation marks.

## 4. LeadForm fields

| Field | Required | Notes |
|-------|----------|-------|
| Name | yes | 2-80 chars |
| Email | yes | validated, normalized lowercase |
| Phone | optional (legal/financial/health), required for logistics quote | E.164-ish, no formatting enforcement |
| Company | optional (logistics required) | - |
| Need / message | yes for consultation | ≤ 1,000 chars; warning not to include sensitive data |
| Program / matter / goal | optional select | channel-specific |
| Consent | yes | explicit, versioned text |

Honeypot field hidden from users; no CAPTCHA in v1 (rate limit + honeypot + duplicate suppression).

## 5. States

- **Idle:** form visible, primary button enabled.
- **Validating:** inline field errors on blur, summary on submit.
- **Submitting:** button busy, fields disabled, no double submit.
- **Success:** replaces the form with a confirmation + response expectation; no PII echoed.
- **Error:** retry path + channel contact email; no stack details.
- **Rate-limited:** "Too many requests - try again later" + `Retry-After` honored.

## 6. Accessibility

- Labels tied to inputs; errors associated via `aria-describedby`.
- `aria-live="polite"` for submit status; focus moves to the first error on failure and to the success heading on success.
- Keyboard operable; 44 px minimum touch targets; contrast AA.
- No timeouts that discard input; no motion beyond a subtle spinner.
- Sticky bar dismissible via keyboard and announced once.

## 7. Analytics hooks

| Event | Payload (no PII) |
|-------|------------------|
| `cta_impression` | channel, placement, locale, article_id? |
| `cta_click` | channel, placement, locale |
| `lead_form_start` | channel, placement, locale |
| `lead_submit` | channel, placement, locale, result (`ok`/`error`/`rate_limited`) |
| `lead_qualified` | channel, source (server-side only) |

No email/phone/name in analytics events. UTM + referrer captured server-side on the lead record.
