# ADR 016 - The apex is a site, not a redirect

**Status:** Decided · 2026-11-07 · **Supersedes:** nothing. **Amends:** ADR 015 (the apex keeps its compat path URLs, but `/` now has content of its own).
**Decision authority:** owner instruction 2026-11-07 ("fully implement the lobby plan").

## Context

ADR 015 put every channel on its own subdomain and left the apex as a doorway: `/` redirected to `SN_DEFAULT_INDUSTRY`. That was correct while the apex had nothing to say. It also hid the two facts a first-time visitor most needs — that there are eleven desks, and that the same machinery is sold as a service — behind a redirect that assumed the visitor already knew which field they were in.

The lobby plan (`.work.biz/plans/20261107-plan-heraldfox-lobby.md`) turns the apex into a directory plus a services page. That is an architectural change, not a copy change: routing, canonical URLs, the sitemap, robots and the funnel all assumed the apex had no indexable content.

## Decision

- **`/` renders the lobby**, in English; `/es` renders it in Spanish. The redirect to the default channel is gone.
- **Four apex routes carry content:** `/`, `/services`, `/privacy`, `/terms` (each with an `/es` twin).
- **Desk plates link to the canonical channel host**, so the lobby is a doorway that hands the visitor to the desk's own origin and `desk_enter` measures the hand-off.
- **The apex is indexable** and has its own sitemap entries; robots.txt no longer disallows the whole host.
- **`services` and `pricing` join the reserved slugs**, in the API validator and in the edge reserved-subdomain list, so a channel can never shadow an apex route.
- **`SN_DEFAULT_INDUSTRY` no longer drives `/`.** It survives only as the fallback home link on a 404.
- **Funnel events from the apex carry no industry.** Migration 016 makes `cta_events.industry_id` nullable and adds `surface`, and `desk_enter` joins the event set. A cross-desk click is attributed to the surface, never to a desk that happened to be first in the list.

## Consequences

- **Positive:** one surface for the network's identity; the services funnel exists; the directory is the internal-link hub that pushes authority into eleven young subdomains; reader capture stays on the desks (D-017), so the apex has no consent surface of its own.
- **Negative:** `/` is now request-rendered (the desk links depend on the host), so it cannot be fully static. The API response behind it is cached for five minutes.
- **Negative:** the apex and the desks both describe the same channels, so copy must not compete for the same query — the lobby targets the network query, desks keep the vertical ones.
- **Neutral:** path URLs (`/heraldfox.com/<slug>`) keep working and keep canonicalising to the channel host. Nothing that worked before 404s now.

## Alternatives considered

| Option | Why rejected |
|--------|--------------|
| Keep the redirect, put the lobby on `www` | Two apex hosts, one canonical, and the bare domain is what people type |
| Serve the lobby on every channel host at `/lobby` | The lobby is the network's, not a desk's; it would duplicate eleven times |
| Static lobby built from the deployment profiles | Desk links are host-dependent; the API is already the source of truth |
| Attribute lobby events to the default desk | Fakes attribution the funnel then reports as real |
