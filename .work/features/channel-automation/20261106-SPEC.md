# Channel automation and free-offer controls - Feature SPEC

**Status:** Implemented (2026-11-06)
**Owner:** Operator (single admin account)
**ADRs referenced:** ADR 013 (lead CTA), ADR 014 (source quality)
**Related plans:** `.work/plans/full/20261105-full-plan.md` §19, `.work.ui/screens/admin-console/20261106-SCREEN-SPEC.md`

## 1. Purpose

Two operator jobs are manual today:

1. **Cadence.** The worker schedules every channel from one environment value
   (`refresh_interval_minutes`, default 720) in
   `apps/api/src/news_api/articles/application/queue.py:133-153`; there is no
   per-channel control in the console.
2. **Offers.** The four free reader offers - consultation request, weekly brief,
   ask-one-question, gated asset - are decided by rendering rules, not operator
   configuration. `cta.asset` presence silently suppresses the brief
   (`apps/web/src/app/[locale]/[industry]/page.tsx:103`, `:138`), and the admin
   `IndustryUpdate` model cannot edit `cta` at all
   (`apps/api/src/news_api/editorial/http/industries.py:53-57`).

This feature gives the operator one place per channel to change the fetch
cadence and switch each free offer on or off. A channel frequency, when set,
wins over the global default.

### 1.1 Research - what is "free" in a channel today

| Surface | Free to reader | Controlled by | Operator control before | Decision |
|---------|----------------|---------------|--------------------------|----------|
| Consultation request | yes (routed to a partner, no fee) | `cta.kind`, `LeadForm` | always on | offer switch `consultation` |
| Weekly brief | yes (email signup) | `BriefSignup`, hardcoded per page | always on unless an asset exists | offer switch `brief` |
| Ask one question | yes (one written question) | `AskQuestion`, article page | always on | offer switch `question` |
| Gated reference asset | yes (waitlist for a dated document) | `cta.asset` + `lib/assets.ts` | on only when the slug resolves | offer switch `asset` |
| RSS feed | yes | `/{industry}/feed.xml` | follows channel enablement | unchanged |
| Public API reads | yes | `/v1/news`, `/v1/news/bundle` | follows channel enablement | unchanged |
| Search, topic hubs, briefs archive | yes | channel routes | always on | unchanged |

Only the four offer rungs have a per-channel on/off decision worth operator
control; the RSS/API/archive surfaces are channel features, not offers. Controlling
the offer rungs here avoids a second settings system for features that already
follow `industries.enabled`.

## 2. In scope / Out of scope

**In scope**

- `industries.fetch_interval_minutes` (nullable) and `industries.auto_fetch_enabled`.
- `industries.offers` JSONB with four canonical switches.
- Scheduler honoring the channel override and the auto-fetch flag.
- Admin API + Channels tab controls for cadence and offers.
- Public channel payload carrying the effective offers.
- Web pages rendering only active offers.

**Out of scope**

- Per-source polling schedules (`sources.poll_interval_min` stays declarative).
- New gated assets or new offer kinds.
- Editing offer copy or qualification options from the console.
- Changing the global default from the console (it stays deployment config).
- Delivery of the weekly brief (U8).

## 3. Domain language

| Term | Meaning |
|------|---------|
| default cadence | `REFRESH_INTERVAL_MINUTES` from `.env.<env>`; deployment-level |
| channel cadence | `industries.fetch_interval_minutes`; `NULL` means "use default" |
| auto-fetch | whether the scheduler may enqueue this channel; manual refresh is unaffected |
| offer | a free reader action: `consultation`, `brief`, `question`, `asset` |
| secondary offer | `brief` or `asset`; at most one is on (the existing one-rung rule) |

## 4. Behavioural spec

**Cadence**

- **R1.** The worker MUST keep scheduling automatic refreshes; this feature does
  not replace the scheduler.
- **R2.** For a channel with `fetch_interval_minutes = N`, the scheduler MUST use
  `N` minutes, not `REFRESH_INTERVAL_MINUTES`.
- **R3.** For a channel with `fetch_interval_minutes IS NULL`, the scheduler MUST
  use `REFRESH_INTERVAL_MINUTES`.
- **R4.** With `auto_fetch_enabled = false`, the scheduler MUST NOT enqueue that
  channel. A manual refresh triggered from the console or CLI MUST still work.
- **R5.** Accepted cadence values are 5-1440 minutes. `null` clears the override.
- **R6.** A cadence change takes effect on the next scheduler tick, based on the
  last `trigger="schedule"` run.

**Offers**

- **R7.** The effective offers are the four booleans in
  `industries.offers`, defaulted per R8.
- **R8.** Defaults when a channel has never been configured:
  `consultation=true`, `question=true`, `asset=<cta.asset present>`,
  `brief=!asset`. This preserves today's one-rung behaviour.
- **R9.** `brief` and `asset` MUST NOT both be true. A write that attempts it is
  rejected (422).
- **R10.** `asset=true` requires a non-empty `cta.asset`. A write that attempts
  it without one is rejected (422).
- **R11.** An offer with `false` MUST NOT render on any public page: no form, no
  section, no CTA link, no sticky bar, no dead `#brief-signup` anchor.
- **R12.** The public channel payload (`GET /v1/industries/{slug}` and the bundle
  `data.industry`) MUST expose the effective offers so the web renders from the
  API, not from duplicated rules.
- **R13.** The admin records every cadence and offer change in `audit_events`
  (`industry.update`).

**Admin**

- **R14.** The Channels tab shows the deployment default cadence, each channel's
  override, and its effective cadence.
- **R15.** The Channels tab lets the operator set `auto_fetch_enabled`, choose
  default vs custom cadence, and switch the four offers without editing JSON.
- **R16.** The UI enforces R9/R10 before submit and shows the API detail when a
  write is rejected.

## 5. Data model

| Field | Table | Type | Notes |
|-------|-------|------|-------|
| `fetch_interval_minutes` | `industries` | `INTEGER NULL` | 5-1440 check; `NULL` = default |
| `auto_fetch_enabled` | `industries` | `BOOLEAN NOT NULL DEFAULT TRUE` | scheduler gate |
| `offers` | `industries` | `JSONB NOT NULL DEFAULT '{}'` | booleans; effective map computed |

No PII. Migration `013_channel_automation.sql` is idempotent.

## 6. APIs

- `PATCH /v1/admin/industries/{slug}` accepts
  `fetch_interval_minutes` (int|null), `auto_fetch_enabled` (bool), `offers`
  (partial map of the four booleans; server merges then validates).
- `GET /v1/admin/industries` returns each channel's raw and effective cadence,
  `auto_fetch_enabled`, the effective `offers`, and
  `defaults.fetch_interval_minutes`.
- `GET /v1/industries/{slug}` and the bundle industry object add `offers`.
- `POST /v1/admin/industries` accepts optional `offers`; defaults per R8.

## 7. Invariants

- **I1.** A channel always has exactly four effective offer keys.
- **I2.** The scheduler never uses a channel value outside 5-1440.
- **I3.** Disabling auto-fetch never blocks a manual run.
- **I4.** No public page links to an offer section that is not rendered.

## 8. Error model

RFC 7807 via `ValidationProblem` / `NotFound` / `Conflict`. Validation messages
name the field and the allowed range or the conflicting pair.

## 9. Observability

- `scheduler.enqueued` log gains `interval_minutes` and `schedule_source`
  (`channel` | `default`).
- `industries.fetch_interval_minutes` / `auto_fetch_enabled` are visible in the
  admin payload; no new metric in v1.

## 10. Security

Admin mutations keep the existing session + CSRF guard (`admin_mutation`), and
the channel slug comes from the path. Offer values are an allow-list of four
booleans; no user copy or HTML is accepted. Public reads expose booleans only.

## 11. i18n

Every new console string lands in both catalogs (`en`, `es`). The public pages
use existing offer copy; no new public strings except the asset link label.
