# Ingestion and AI Summary Pipeline - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 007/010 · **Owner:** engineering
**Needs:** owner ratification of ADR 007/010; otherwise nothing.

**ADRs referenced:** 002 (database), 003 (Redis), 007 (i18n), 010 (pipeline), 011 (auth)
**Related plans:** `.work/plans/foundation/20261105-02-integration-resources.md`, `.work/plans/foundation/20261105-04-foundation-architecture.md`

## 1. Purpose

Turn approved publisher feeds into scored, deduplicated, language-partitioned, copyright-safe article bundles - twice a day by default, on demand when needed, observably, and without letting upstream or AI failures stop publication.

## 2. In scope / Out of scope

**In:** scheduled polling (default every 12 h), manual forced refresh, conditional GET, parse/normalize, declared-language assignment, scoring, dedupe/corroboration, retention, AI summaries and desk briefs per language, incremental reuse, worker queue, run telemetry.
**Out:** language detection, translation, full-text storage, image rehosting, paywall handling, crawling article bodies, newsletter generation, social posting.

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Source** | A publisher feed bound to one channel and one declared language |
| **Candidate** | A parsed feed entry before scoring |
| **Pool** | All candidates of one language for one channel; the only unit that is scored/deduped/layouted |
| **Score** | Deterministic relevance number (`score_items`) |
| **Corroboration** | Count of independent sources reporting the same story **within a language pool** |
| **Summary** | Original 2-4 sentence AI text in the article's language |
| **Desk brief** | 5-line overview of one language bundle |
| **Refresh run** | One execution of fetch → partition → score → dedupe → summarize → persist |
| **Force refresh** | A manual run that bypasses the schedule but not the single-flight lock |

## 4. Behavioural spec (rules)

**R1. Scheduling.** The worker schedules one run per enabled channel every `REFRESH_INTERVAL_MINUTES` (env, default **720** = twice a day), staggered 0-10 min across channels. A single-flight Redis lock (`ingest:lock:{industry}`) prevents concurrent runs per channel. Schedule state is persisted (`refresh_runs`), not held in memory. No public read triggers ingestion.

**R2. Fetch safety.** Only `https` feed URLs are fetched (HTTP requires explicit per-source approval stored as `allow_http=true`). The fetcher blocks private/loopback/link-local/metadata IP ranges, re-checks DNS after redirects, follows at most 3 redirects, caps response size at 5 MB, uses a 12 s total / 6 s connect timeout, and sends a fixed User-Agent with a contact URL. Violations mark the source `blocked` and raise an alert.

**R3. Conditional GET.** Each source stores `etag` and `last_modified`; requests send `If-None-Match`/`If-Modified-Since`; `304` counts as success and updates `last_success_at` without parsing.

**R4. Parsing and normalization.** Parse RSS 2.0 and Atom; extract title, link, published/updated, summary/description, author/publisher. Strip HTML tags and entities from text fields; unescape twice; repair common UTF-8-as-Latin-1 mojibake; collapse whitespace; cap title at 300 chars and excerpt at 280 chars; reject entries with no title or no valid URL.

**R5. Canonicalization.** Normalize the URL: lowercase scheme/host, strip `www.`, fragments, trailing slashes, and tracking params (`utm_*`, `fbclid`, `gclid`, `ref`); prefer `<link rel="canonical">` when present. Upsert key = `(canonical_url)`, unique globally; an article belongs to exactly one channel. Item id = `<source_id>:<hash(canonical_url, casefolded title)>`.

**R6. Language (declared, then partitioned).** `sources.language` is mandatory and MUST be a supported locale (`en`, `es` at launch); every parsed item inherits it. Seeds declare `language`. No heuristic detection. Candidates are partitioned by language **before** scoring; each pool is scored, deduped, layouted, and summarized independently. There is **no cross-language dedupe** and no mixed-language bundle. A source with an unsupported language code is rejected at save time (`422`) and never fetched.

**R7. Scoring.** Port the reference algorithm: `score = (keyword_weight × topic_multiplier × topic_weight + trust_weight × source_trust + title_length_bonus) × recency`, where `recency = max(0.15, 0.5^(age_hours/72))`; pinned items get `+5.0`; items below `min_score=0.35` are excluded unless pinned; `require_topic_match` defaults true. Topic matching uses `keywords_<locale>` when present, else English `keywords`. All constants live in `apps/api/config/scoring.json`, not code.

**R8. Dedupe and corroboration.** Within a language pool only: cluster by title similarity ≥ 0.72 using Unicode-aware tokenization; keep the highest-scoring representative; attach `corroboration` (cluster size) and `corroborating_sources`; add `+0.15 × (corroboration-1)` to the score; single-source items with `trust < 0.8` get `-0.12` and `verification = single-source`; otherwise `corroborated` (≥2) or `trusted-source`.

**R9. Retention and purge.** Visible window: `retention.max_age_days` (default 7). Rows are purged after 30 days by a nightly job. A refresh never deletes an article still inside the window, even if it dropped out of the feed. Pinned seeds are exempt from the age filter (R18).

**R10. Persistence.** The run writes candidates in one transaction per batch (upsert by canonical URL), then updates `refresh_runs` with `{started_at, finished_at, status, stats}`. `stats` includes `feeds_polled`, `http_304`, `items_fetched`, `new`, `updated`, `duplicates`, `scored_out`, `summarized`, `errors`, `per_language`.

**R11. AI provider and model.** DeepSeek, base `https://api.deepseek.com`, OpenAI-compatible `POST /chat/completions`, model **`deepseek-flash`** (DeepSeek-V4.1-Flash). `AI_MODEL` may override; legacy ids (`deepseek-v4-flash`, `deepseek-chat`, `deepseek-reasoner`) are rejected in new config. Thinking disabled; temperature 0.4 prose / 0.3 picks; timeouts 45 s desk, ≥120 s items, ≥60 s picks. Keys resolve `AI_API_KEY` → `DEEPSEEK_API_KEY`; never logged.

**R12. AI outputs and prompts.** Per language: a 5-line desk brief (≤ 1200 chars, ≤ 12 headlines in the prompt), one 2-4 sentence paragraph per article (≤ 900 chars), and 1 lead + N favorite picks by id from the top 20 candidates. Prompts are versioned EN/ES tables in `apps/api/config/prompts/{en,es}.json` with `PROMPT_VERSION=1`; the JSON contract is language-independent. Only new/changed items are sent to the model.

**R13. Validation, fail-open, and injection resistance.** AI errors/timeouts/invalid output never block publication: the item is published without a summary and statuses record `partial`/`failed`. Output must be plain text, ≥ 80 chars, 2-4 sentences, no URLs/domains/HTML, and must not copy the title verbatim; rejects are retried once, then dropped. Feed content is data only: no tool calls, no system-prompt mutation, no retrieval; output is never executed or used for ranking.

**R14. Copyright-safe storage.** Never store the article body or images; store only title, canonical URL, publisher, published time, topics, and the original summary. Every published item links to the publisher and shows attribution. A takedown (`status=hidden`, optional source block) takes effect within 24 h and is audited.

**R15. Incremental behavior.** On a normal run, existing valid summaries are reused by `(canonical_url, language)` when the language matches; only new/changed items are sent to the model. `prompt_version` bumps do not invalidate cached summaries on incremental runs; `full_reset=true` (admin-only, audited) regenerates them.

**R16. Worker and retries.** The API enqueues `{industry, mode}` to Redis Stream `news:jobs`; the worker consumes with group `worker`, acking only after success. Failures retry 3 times with exponential backoff (1, 5, 25 min), then move to `news:jobs:dead` and raise an alert. A failed feed contributes nothing and the run finishes `partial`.

**R17. Manual forced refresh.** `POST /v1/admin/refresh` `{industry, force:true}` (admin auth) enqueues a run and returns `202` + `run_id`; `GET /v1/admin/refresh/{run_id}` reports status/stats. `force` bypasses the schedule, not the lock; a concurrent run returns `409` with the active `run_id`. CLI equivalent: `python -m news_api.cli refresh --industry all --force` (wrapped by `./bin/start.sh refresh`). Manual runs are audited.

**R18. Seeds.** A curated allowlist (`config/seeds.json`) can inject items with `pinned=true`; seeds declare `language`, bypass fetch, and are **exempt from the age filter** while pinned. Seeds still go through scoring, dedupe, and summary.

**R19. Cost controls.** Per-run cap `AI_MAX_ITEMS_PER_RUN` (default 60 per channel) and monthly cap `AI_MONTHLY_BUDGET_USD` are checked before each model call; reaching the cap stops summarization for the run (headlines still publish) and raises an alert.

## 5. Data model

Writes `articles`, `article_topics`, `refresh_runs`, `sources.fetch_state`. Full columns in doc 04 §4. Additional constraints:

- `articles.canonical_url` UNIQUE (global).
- `articles.language ∈ supported locales` (validated at ingest).
- `articles.status ∈ {draft, published, hidden, archived}`.
- `summary` nullable; `summary_language = articles.language`.
- `summary_source ∈ {ai, editor, null}`.
- `refresh_runs.status ∈ {queued, running, ok, partial, failed}`; `trigger ∈ {schedule, manual, reset}`.

## 6. APIs

Internal worker consumes the stream. Admin: `POST /v1/admin/refresh`, `GET /v1/admin/refresh/{run_id}`, `POST /v1/admin/sources/{id}/test`, `POST /v1/admin/sources/{id}/force-fetch`. Public reads are unchanged (see news-api SPEC R16).

## 7. Invariants

- **I1** No article body/media is stored.
- **I2** A published article always has a title, canonical URL, publisher, `published_at`, and `language`.
- **I3** Re-running a refresh never creates duplicates (canonical URL unique) and never removes in-window items.
- **I4** AI failure never changes `status` from `published`.
- **I5** Every refresh run leaves exactly one `refresh_runs` row with a terminal status.
- **I6** A source marked `blocked` is never fetched until re-enabled by an admin.
- **I7** No bundle contains an item whose `language` differs from the bundle language.
- **I8** Scheduled runs never overlap per channel; manual runs collapse into the same lock.

## 8. Error model

Source errors: `http_error`, `timeout`, `parse_error`, `blocked`, `too_large`, `invalid_language`. Pipeline errors: `lock_held` (`409`), `db_error` (retry), `ai_error` (fail-open), `budget_exceeded` (stop summaries). All recorded in `refresh_runs.stats` and metrics; never surfaced as a public 5xx.

## 9. Observability

`ingest_fetch_total{source,status}`, `ingest_fetch_duration_seconds`, `ingest_items_total{industry,language,result}`, `ingest_lag_seconds{industry}`, `articles_scored_total`, `refresh_runs_total{trigger,status}`, `refresh_duration_seconds`, `summaries_generated_total{language,status}`, `ai_tokens_total{model}`, `ai_estimated_cost_usd_total`, `queue_depth{stream}`.

## 10. Security

Threat model T5 (SSRF), T6 (prompt injection), T11 (supply chain), T12 (data loss). Feed URLs are admin-only; AI inputs are truncated and validated; worker runs as non-root with a read-only FS except a temp dir.

## 11. i18n

Language is assigned at ingest, never inferred; each bundle is single-language. Summaries and desk briefs are generated in the bundle language with per-language prompts. Adding a locale = catalog + prompt table + source languages + registry entry; no schema change.
