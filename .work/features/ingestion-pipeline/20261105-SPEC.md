# Ingestion and AI Summary Pipeline - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 010 · **Owner:** engineering
**Needs:** owner ratification of ADR 010; otherwise nothing.

**ADRs referenced:** 002 (database), 003 (Redis), 010 (pipeline), 011 (auth)
**Related plans:** `.work/plans/foundation/20261105-02-integration-resources.md`, `.work/plans/foundation/20261105-04-foundation-architecture.md`

## 1. Purpose

Turn approved publisher feeds into a scored, deduplicated, locale-aware, copyright-safe article stream - automatically, observably, and without letting upstream or AI failures stop publication.

## 2. In scope / Out of scope

**In:** scheduled polling, conditional GET, parse/normalize, language detection, scoring, dedupe/corroboration, retention, AI summaries (EN/ES), incremental reuse, worker queue, refresh telemetry, manual refresh.
**Out:** full-text storage, image rehosting, paywall handling, crawling article bodies, newsletter generation, social posting.

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Source** | A publisher feed bound to one channel |
| **Candidate** | A parsed feed entry before scoring |
| **Score** | Deterministic relevance number (`score_items`) |
| **Corroboration** | Count of independent sources reporting the same story |
| **Summary** | Original 2-4 sentence AI text derived from title + excerpt |
| **Desk brief** | 5-line overview of a channel's current top items |
| **Refresh run** | One execution of fetch → score → dedupe → summarize → persist |

## 4. Behavioural spec (rules)

**R1. Scheduling.** Each enabled source is polled every `source.poll_interval_min` (default 10, min 5). A single-flight Redis lock (`ingest:lock:{industry}`) prevents concurrent runs per channel; a global lock prevents overlapping full refreshes.

**R2. Fetch safety.** Only `https` feed URLs are fetched (HTTP requires explicit per-source approval stored as `allow_http=true`). The fetcher blocks private/loopback/link-local/metadata IP ranges, re-checks DNS after redirects, follows at most 3 redirects, caps response size at 5 MB, uses a 10 s timeout, and sends a fixed User-Agent with a contact URL. Violations mark the source `blocked` and raise an alert.

**R3. Conditional GET.** Each source stores `etag` and `last_modified`; requests send `If-None-Match`/`If-Modified-Since`; `304` counts as success and updates `last_success_at` without parsing.

**R4. Parsing and normalization.** Parse RSS 2.0 and Atom; extract title, link, published/updated, summary/description, author/publisher. Strip HTML tags and entities from text fields; collapse whitespace; cap title at 300 chars and excerpt at 600 chars; reject entries with no title or no valid URL.

**R5. Canonicalization.** Normalize the URL: lowercase scheme/host, strip `utm_*`, `fbclid`, `gclid`, fragments, and trailing slashes; prefer `<link rel="canonical">` when present. Upsert key = `(canonical_url)`, unique globally; an article belongs to exactly one channel.

**R6. Language.** Use the feed's declared `language` when valid; otherwise detect from title/excerpt (stopword heuristic); store `language` (BCP 47). Items whose language is unsupported are stored but not published until a locale is added.

**R7. Scoring.** Port the reference algorithm: `score = (keyword_weight × topic_multiplier × topic_weight + trust_weight × source_trust + title_length_bonus) × recency`, where `recency = max(0.15, 0.5^(age_hours/72))`; pinned items get `+5.0`; items below `min_score=0.35` are excluded unless pinned; `require_topic_match` defaults true. All constants live in `config/scoring.json`, not code.

**R8. Dedupe and corroboration.** Cluster candidates by title similarity ≥ 0.72 (token-set ratio); keep the highest-scoring representative; attach `corroboration` (cluster size) and `corroborating_sources` (capped at 5); add `+0.15 × (corroboration-1)` to the score; single-source items with `trust < 0.8` get `-0.12` and `verification = single-source`; otherwise `corroborated` (≥2) or `trusted-source`.

**R9. Retention and purge.** Visible window: `retention.max_age_days` (default 7). Rows are purged after 30 days by a nightly job. A refresh never deletes an article that is still inside the window, even if it dropped out of the feed.

**R10. Persistence.** The run writes candidates in one transaction per batch (upsert by canonical URL), then updates `refresh_runs` with `{started_at, finished_at, status, stats}`. `stats` includes `feeds_polled`, `http_304`, `items_fetched`, `new`, `updated`, `duplicates`, `scored_out`, `summarized`, `errors`.

**R11. AI summaries.** For each published item missing a `summary` for a locale, call an OpenAI-compatible chat endpoint with a fixed system prompt and `title` + `excerpt` only. Output: 2-4 sentences, ≤ 900 chars, no URLs, no HTML, no quotes attributed to people unless present in the input. Store `summary`, `summary_language`, `summary_source='ai'`, `summary_version`.

**R12. Desk brief.** Once per channel/locale per run, generate a 5-line brief (≤ 1200 chars, ≤ 12 headlines in the prompt) and store it with `ai_summary_model` + `ai_summary_language`.

**R13. Fail-open and injection resistance.** AI errors/timeouts/invalid output never block publication: the item is published without a summary and `item_summary_status` records `partial`/`failed`. Feed content is treated strictly as data: no tool calls, no system-prompt mutation, no retrieval; output is validated before storage; model output is never executed or used for ranking.

**R14. Copyright-safe storage.** Never store the article body or images; store only title, canonical URL, publisher, published time, topics, and the original summary. Every published item links to the publisher and shows attribution. A takedown (`status=hidden`, optional source block) takes effect within 24 h and is audited.

**R15. Incremental behavior.** On a normal run, existing valid summaries are reused by `(canonical_url, language)` when `summary_version >= prompt_version`; only new/changed items are sent to the model. `full_reset=true` (admin-only) wipes and rebuilds summaries; it is audited.

**R16. Worker and retries.** The API enqueues `{industry, mode}` to Redis Stream `news:jobs`; the worker consumes with group `worker`, acking only after success. Failures retry 3 times with exponential backoff (1, 5, 25 min), then move to `news:jobs:dead` and raise an alert.

**R17. Manual refresh.** `POST /v1/admin/refresh` (admin auth) enqueues a run and returns `202` + `run_id`; `GET /v1/admin/refresh/{run_id}` reports status/stats. Idempotency-Key supported.

**R18. Seed content.** A curated allowlist (`config/seeds.json`) can inject items with `pinned=true`; seeds bypass fetch but still go through scoring/dedupe/summary.

## 5. Data model

Writes `articles`, `article_topics`, `refresh_runs`, `sources.fetch_state`. Full columns in doc 04 §4. Additional constraints:

- `articles.canonical_url` UNIQUE (global).
- `articles.status ∈ {draft, published, hidden, archived}`.
- `articles.language` BCP 47 text.
- `summary` nullable; `summary_source ∈ {ai, editor, null}`.
- `refresh_runs.status ∈ {queued, running, ok, partial, failed}`.

## 6. APIs

Internal: worker consumes the stream; admin endpoints `POST /v1/admin/refresh`, `GET /v1/admin/refresh/{run_id}`, `POST /v1/admin/sources/{id}/test`. Public surface is unchanged (see news-api SPEC).

## 7. Invariants

- **I1** No article body/media is stored.
- **I2** A published article always has a title, canonical URL, publisher, and `published_at`.
- **I3** Re-running a refresh never creates duplicates (canonical URL unique) and never removes in-window items.
- **I4** AI failure never changes `status` from `published`.
- **I5** Every refresh run leaves exactly one `refresh_runs` row with terminal status.
- **I6** A source marked `blocked` is never fetched until re-enabled by an admin.

## 8. Error model

Source errors: `http_error` (4xx/5xx), `timeout`, `parse_error`, `blocked`, `too_large`. Pipeline errors: `lock_held` (skip), `db_error` (retry), `ai_error` (fail-open). All recorded in `refresh_runs.stats` and metrics; never surfaced as a public 5xx.

## 9. Observability

`ingest_fetch_total{source,status}`, `ingest_fetch_duration_seconds`, `ingest_items_total{industry,result}`, `ingest_lag_seconds`, `articles_scored_total`, `refresh_runs_total{status}`, `summaries_generated_total{locale,status}`, `ai_tokens_total`, `ai_estimated_cost_usd_total`, `queue_depth{stream}`.

## 10. Security

Threat model T5 (SSRF), T6 (prompt injection), T11 (supply chain), T12 (data loss). Feed URLs are admin-only; AI inputs are truncated and validated; worker runs as non-root with read-only FS except a temp dir.

## 11. i18n

Summaries are generated per locale from the same title/excerpt; `summary_language` is stored; missing locale → `summary: null` + availability list (news-api R13). Desk briefs are per locale.
