# Lead and contact attribution - Feature SPEC

**Status:** Implemented (2026-11-06)
**Owner:** operator
**Related:** `publishing/http/{leads,contact}.py`, `editorial/http/contacts.py`

## 1. Purpose

Make every inquiry carry the same non-PII attribution: source page, normalized
UTM, hashed session, hashed network/device identifiers, and a coarse country code
when the edge provides one. Contact messages had none of this, and leads could
not be joined to CTA events.

## 2. Rules

- **R1.** Contact messages store `source_page`, `utm`, `ip_hash`, `ua_hash`,
  `country`, and `session_hash`.
- **R2.** Leads store `country` and `session_hash` in addition to the existing
  attribution fields.
- **R3.** `country` comes only from a configured trusted edge header
  (`GEO_COUNTRY_HEADER`); empty disables it. A client-supplied header is not
  trusted unless the edge overwrites it.
- **R4.** Raw IP addresses are never stored. `ip_hash` is a peppered SHA-256.
- **R5.** UTM is reduced to the five campaign keys; unknown keys and values over
  120 characters are dropped.
- **R6.** `session_hash` matches the hash used by `/v1/cta-events`, so a lead can
  be joined to its CTA journey.
- **R7.** The admin contact inbox can list, filter, mark `new|read|closed`, and
  erase a message. It exposes attribution but not IP/UA hashes.
- **R8.** The public privacy copy states what is stored and that raw IP is not.

## 3. Data

`leads`: `country TEXT`, `session_hash TEXT`.
`contact_messages`: `source_page TEXT`, `utm JSONB`, `ip_hash TEXT`,
`ua_hash TEXT`, `country TEXT`, `session_hash TEXT`.

## 4. APIs

- `GET /v1/admin/contacts?industry=&status=&limit=`
- `PATCH /v1/admin/contacts/{id}` `{status}`
- `DELETE /v1/admin/contacts/{id}`
- Leads already expose `utm`, `country`, `session_hash` in the admin DTO.
