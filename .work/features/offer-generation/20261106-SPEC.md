# Offer issue generation - Feature SPEC

**Status:** Implemented (2026-11-06) - drafts only; publish/email/reviewer out of scope
**Owner:** operator
**ADRs referenced:** ADR 013 (offer ladder), ADR 014 (source quality)
**Related plans:** `.work.biz/strategy/20261106-ai-offer-system.md`, `.work.biz/plans/plan_kev-digest.md`

## 1. Purpose

The free offers are capture-only. This feature makes the machine side ready:

- store dated offer issues;
- generate a draft issue from citable public records;
- draft the plain-language rows with the existing AI client, with a deterministic fallback;
- schedule draft generation automatically, weekly or monthly;
- never publish automatically.

Email delivery and named reviewers stay out of scope. A generated issue is a draft with a reviewer field left empty. The operator can inspect it before any publish path exists.

## 2. Jurisdiction policy

**Decision: US first, scope stated in the issue.**

- Every regulatory reference is scoped to `US` in v1. The title and the issue carry the scope.
- The Federal Register is the US source. It does not claim EU coverage.
- CISA KEV is `global` because the catalog is a US publication about vulnerabilities that affect vendors worldwide. The issue title says `CISA KEV`, not `global regulation`.
- EU and other jurisdictions are added as **separate adapters with their own scope**, not by widening a title. A future `eu_eurlex` adapter would produce an issue with `scope = "EU"` or a `US + EU` issue only after both adapters run and a reviewer signs the combined table.
- The generator rejects an issue whose `scope` is empty or whose adapter's `default_scope` differs from the definition without an explicit override.

This resolves the current ambiguity: a scope is a property of the source adapter, not a marketing claim.

## 3. In scope / Out of scope

**In scope**

- migration `014_offer_issues.sql`;
- `offer_issues` storage and repo;
- offer definitions config: legal and cybersecurity;
- source adapters: Federal Register (US) and CISA KEV (global);
- deterministic row building + optional AI paraphrasing;
- CLI: build, list, show;
- worker scheduler: weekly/monthly draft generation through the existing Redis job stream;
- admin read/build endpoints and an Offers tab in the editorial console;
- tests with fixtures, no live network.

**Out of scope**

- email delivery, unsubscribe, double opt-in (U8/D-002);
- reviewer sign-off and public publish (the `publish` path is not built);
- public issue page and archive;
- EU/Asia adapters;
- the other six reference offers;
- per-offer billing or partner routing changes.

## 4. Domain language

| Term | Meaning |
|------|---------|
| offer definition | a configured generator: channel, slug, adapter, cadence, scope, row cap |
| raw record | one source record normalized to a common shape |
| issue | a dated set of rows for one channel and one offer |
| draft | a generated issue with no reviewer and no publish timestamp |
| scope | the jurisdiction the issue claims, carried in the title and the payload |
| adapter | code that turns one public source into raw records |

## 5. Behavioural rules

- **R1.** `offer_issues` has one row per `(industry_id, offer_slug, issue_date)`.
- **R2.** An issue has a non-empty `scope` and `title`; the title contains the scope label for regulatory offers.
- **R3.** The builder writes `status = draft` only after every row has a source URL and the row count is within the definition cap.
- **R4.** If a source returns no usable rows, the issue is `empty`; it is not published and no email is sent.
- **R5.** AI may paraphrase a row. If AI is disabled or fails, the builder uses source text and records `drafted_by = fallback`.
- **R6.** The builder never invents a date, a source URL, or a jurisdiction. A record without both a date and a URL is dropped.
- **R7.** The scheduler creates at most one issue per offer per due date. A queued/building/draft/empty issue blocks a duplicate.
- **R8.** The scheduler generates drafts only. No code path publishes or emails.
- **R9.** Manual CLI builds are idempotent: re-running for the same date updates the draft.
- **R10.** The generator uses the existing SSRF guard and size cap for every outbound source fetch.
- **R11.** The worker logs the offer slug, issue date, adapter, row count, and status; it never logs source bodies.

## 7. Configuration

`apps/api/config/offers.json`:

```json
{
  "legal": {
    "offer_slug": "legal-regulatory-calendar",
    "name": "US Regulatory Calendar",
    "adapter": "federal_register",
    "scope": "US",
    "cadence": {"kind": "monthly", "weekday": 1, "nth": 1},
    "lookback_days": 120,
    "max_rows": 12,
    "enabled": true
  },
  "cybersecurity": {
    "offer_slug": "cybersecurity-kev-digest",
    "name": "CISA KEV Digest",
    "adapter": "cisa_kev",
    "scope": "global",
    "cadence": {"kind": "weekly", "weekday": 2},
    "lookback_days": 28,
    "max_rows": 12,
    "enabled": true
  }
}
```

`weekday` uses Python Monday=0. `nth` is 1-based within the month.

## 8. APIs / CLI

- `GET /v1/admin/offers?industry=&status=` (admin auth): list issues, no PII.
- `GET /v1/admin/offers/{id}` (admin auth): full issue.
- CLI `python -m news_api.cli offer build --industry legal --offer legal-regulatory-calendar [--date YYYY-MM-DD] [--dry-run]`
- CLI `python -m news_api.cli offer list [--industry legal]`
- CLI `python -m news_api.cli offer show <id>`

No public endpoint in v1. A public issue page is a later feature; the draft is not reader-facing.

## 9. Error model

- `NotFound` for unknown channel/definition/issue.
- `ValidationProblem` for bad date, unknown offer, scope mismatch.
- `UpstreamError` is not introduced; adapter failures mark the issue `failed` with a short reason and log the type.
- The CLI exits 2 on validation, 1 on build failure.

## 10. Security

- Outbound URLs come from config, not request input. Still validate with `validate_fetch_url` and cap the body at 5 MB.
- No PII is fetched or stored. No email addresses.
- Admin read requires the existing session auth; no mutation endpoint in v1.
- No autopublish.
- The source body is not logged.

## 11. Observability

### 16.1 AI cost note

The first legal prompt used 2,510 prompt tokens and 6,303 completion tokens at
`max_tokens=8000`. At the configured DeepSeek prices that is about $0.008 per
issue, well inside the $20 monthly cap. A 2,400-token cap returned an empty
completion for the 12-row prompt, so the builder uses 8,000 and falls back to
source rows if the model still returns invalid JSON.
