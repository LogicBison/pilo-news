# SPEC — source availability, permission and acquisition

**Status:** Implemented (2026-11-10) · **Needs:** owner review of the two added primary sources; no code work open.
**Scope:** how the platform keeps sources readable — permission record, refusals, credentials, primary-source preference, publisher allowlisting.
**Builds on:** `.work/features/fetch-safety/20261109-SPEC.md` (identity, robots, pacing).

---

## 1. Problem

Fetch-safety made the crawler polite. It did not answer "may we read this, and what do we do when the answer is no". Two of fifty sources were refused by their own robots file and were retired by hand; a `403` looked like any other error and was retried every run; there was no place to record a licence or a credential; and coverage counted configured sources, not readable ones.

## 2. Non-goals

- Browser impersonation. The UA stays `HeraldFoxBot/1.0 (+https://heraldfox.com/bot)`; a publisher-requested UA is a per-source header, never a global disguise.
- Scraping pages behind a login or a paywall without a licence.
- Automatic licence purchase.

## 3. Requirements

### R1 — Refusals are a state, not an error
`401`/`403` returns outcome `denied`; the host is parked for seven days (`FETCH_DENIED_COOLDOWN_S`) with `cooldown_reason=denied`, the fail streak is left alone, and the run stats count `denied` separately from `blocked` so a permanent refusal cannot masquerade as load.

*Accept:* 401 test → `denied` + host cooldown; denied is excluded from the blocked share that flips a run to `partial`.

### R2 — A 403 challenge is a challenge
A `403` body matching the challenge signatures is classified `challenge` (one-hour cooldown) instead of a generic error. WAFs use 403 more often than 200.

*Accept:* 403 + Cloudflare body → `challenge`.

### R3 — Permission ledger
`permission_state` (`unknown`/`allowed`/`denied`/`licensed`), `robots_checked_at`, `robots_hash` (sha256 of the exact robots body), `robots_crawl_delay`. Written by `verify-sources`, which is the moment an operator asks the question; the fetch path stays write-free.

*Accept:* a verify run leaves all four populated; the hash changes when the robots text changes.

### R4 — Licensed feeds
Per-source `auth_type` (`none`/`header`/`basic`), `auth_header_name`, `auth_secret_ref` (an environment variable name, never the secret). A publisher-requested `User-Agent` uses `auth_type=header` with `auth_header_name=User-Agent`; that is the only supported identity override.

*Accept:* header sent from the environment; missing variable logs once and sends no credential; no secret in the database or the admin payload.

### R5 — Availability is measured
`verify-sources` reports `healthy`, `minimum: 4`, `ok` per channel; the CLI exits non-zero when any source fails **or** a channel falls below the floor. Coverage (configured) and availability (readable) are separate numbers.

*Accept:* a channel with 3 healthy sources exits 1 with the reason in `warnings`.

### R6 — Primary sources first
Government, regulator and exchange feeds are preferred when a desk needs a replacement: explicit terms, stable URLs, no WAF. Added 2026-11-10: CISA News (cybersecurity), SEC Press Releases (financial).

*Accept:* both grade A, `terms_url` set, availability floor met on both channels.

### R7 — Publisher allowlisting
The `/bot` page carries the identity, the pacing, how to block us, and how to allowlist us. No nav entry.

*Accept:* EN + ES e2e cover the page; the allowlist block names the UA and the opt-in path.

## 4. Data

Migration `017_source_permissions.sql`: seven additive columns on `sources`, two `CHECK` constraints. No table rewrite, no backfill; existing rows default to `unknown`/`none`.

## 5. Decisions

1. **No browser UA.** Considered and rejected: a browser identity converts a compliance question into a deception question, and WAFs fingerprint TLS and header order anyway. The legitimate path is per-source credentials and a documented UA.
2. **Denied is a week, not forever.** A licence or a robots edit should be picked up without a deploy; a week bounds the pestering.
3. **Ledger is written by verify, not by fetch.** One write per run instead of one per fetch, and the operator's question is the trigger.
