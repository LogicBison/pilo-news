# Editorial Console (minimal) - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 011 · **Owner:** engineering
**Needs:** owner ratification of ADR 011; otherwise nothing.

**ADRs referenced:** 011 (auth), 006 (channels), 010 (pipeline), 003 (Redis)
**Related plans:** `.work/plans/20261105-personas-v1.md` (editor persona)

## 1. Purpose

Give one to three operators a small, safe admin surface to keep the pipeline healthy: manage sources and topics, pin/hide stories, trigger refreshes, issue API keys, and see what changed - without a full CMS.

## 2. In scope / Out of scope

**In:** login/logout, source CRUD + enable/disable + test fetch, topic weights/keywords, pins, hide/unhide article, trigger refresh + run status, API key create/list/revoke, audit log view, channel enable/disable, theme JSON edit with validation, lead inbox + partner routing, DSAR export/delete.
**Out:** rich-text article authoring, image uploads, scheduling, roles/permissions matrix, approval workflows, multi-editor collaboration (Phase B).

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Operator** | The single admin account in v1 |
| **Pin** | Editorial override that promotes an article into the splash/columns |
| **Hide** | Removes an article from all public surfaces immediately |
| **Run** | One ingestion refresh with stats |
| **Key** | Client API credential (`sn_live_...`) |

## 4. Behavioural spec (rules)

**R1. Login.** `POST /v1/admin/auth/login` accepts email + password, verifies Argon2id hash, rate-limits 5/min/IP, sets an httpOnly `sn_admin` JWT cookie (15 min) + `sn_csrf` cookie, and returns the operator profile. Invalid credentials return the same `401` regardless of which field is wrong (no enumeration).

**R2. Session.** Every admin request validates the JWT signature, expiry, and `jti` against the Redis denylist. Logout adds the `jti` to the denylist and clears cookies. Expired session → `401` with `type=session-expired`; the console redirects to login.

**R3. CSRF.** Every mutating request requires `X-CSRF-Token` equal to the `sn_csrf` cookie value; mismatch/missing → `403`. GET requests are exempt.

**R4. Source management.** Create/update/delete sources with `name`, `feed_url`, `language`, `trust` (0-1), `poll_interval_min` (5-1440), `enabled`, `terms_checked_at`, `terms_url`. `feed_url` must be https and pass the SSRF validator (ingestion R2); duplicate URL per channel → `409`. Delete removes the source but keeps its articles (orphan `source_id` set null).

**R5. Source health and test.** The console lists `last_fetched_at`, `last_success_at`, `status`, `consecutive_failures`, and last error. `POST /v1/admin/sources/{id}/test` performs a one-off conditional fetch (no persistence) and returns status, item count, and parse errors.

**R6. Audit trail.** Every mutation writes `audit_events` (`actor`, `action`, `entity`, `entity_id`, `payload` with before/after hashes, `created_at`). The console shows the last 200 events filterable by action. Audit rows are append-only; no delete endpoint.

**R7. Pins.** Pin/unpin an article with a position (1-5) and weight; a pin promotes the item into the splash and prevents score-based removal. Duplicate position per channel → `409` (replace requires explicit unpin). Pins expire after `pin_expires_at` (default 72 h) to avoid stale heroes.

**R8. Hide/unhide.** Hide requires a reason (free text ≤ 200 chars), takes effect within one cache TTL (≤ 60 s) and is audited; unhide is allowed but audited. Hidden items never appear in public responses (news-api R5).

**R9. Refresh control.** Trigger a run (optionally `industry`, `force`, `full_reset`), see `run_id`, status, trigger (`schedule`/`manual`/`reset`), duration, and stats. `force` bypasses the schedule but not the single-flight lock; only one run per channel at a time (`409` if lock held). `full_reset` requires a typed confirmation and is audited.

**R10. API keys.** Create labeled keys with scopes (`read` only in v1) and a rate limit; the plaintext key is shown exactly once; list shows label, prefix, scopes, `last_used_at`, `enabled`; revoke takes effect immediately. No key value is ever returned again.

**R11. Channel and theme management.** Enable/disable a channel (disabled = 404 publicly), edit `theme` JSON and per-locale disclaimers; the server validates against the theme schema and WCAG AA contrast before saving; invalid input → `422` with field errors.

**R12. Access control.** All `/v1/admin/*` routes require admin auth; there is no public admin route. CORS is disabled for admin routes (same-origin only). Response bodies never include hashes or keys.

**R13. Lead inbox.** The console lists leads filtered by channel and status (`new`, `routed`, `contacted`, `qualified`, `closed`, `spam`), with name/email/phone/need/consent/source. Status changes are audited and write `lead_events`. No lead PII appears in logs; export is explicit.

**R14. Partners.** Manage one active partner per channel (`name`, `contact_email`, `status`, `regions`), assign/reassign leads, and see ack SLA age. A partner can be disabled without deleting historical leads.

**R15. DSAR and retention.** Export a lead as JSON and delete it on request (within 30 days); deletion writes an audit event and leaves no PII. The retention job purges leads older than 24 months (90 days for spam) and CTA events older than 90 days.

## 5. Data model

Reads/writes `sources`, `pins`, `articles.status`, `industries`, `api_keys`, `audit_events`. No new tables; `audit_events.payload` stores hashes and small diffs, never secrets or PII bodies.

## 6. APIs

`POST /v1/admin/auth/login`, `POST /v1/admin/auth/logout`, `GET /v1/admin/me`, `CRUD /v1/admin/sources`, `POST /v1/admin/sources/{id}/test`, `CRUD /v1/admin/topics`, `CRUD /v1/admin/pins`, `POST /v1/admin/articles/{id}/hide|unhide`, `POST /v1/admin/refresh`, `GET /v1/admin/refresh/{run_id}`, `CRUD /v1/admin/api-keys`, `PATCH /v1/admin/industries/{slug}`, `GET /v1/admin/audit`, `GET|PATCH /v1/admin/leads`, `POST /v1/admin/leads/{id}/assign`, `GET /v1/admin/leads/{id}/export`, `DELETE /v1/admin/leads/{id}`, `CRUD /v1/admin/partners`.

## 7. Invariants

- **I1** No admin route responds without a valid session.
- **I2** Every mutation produces exactly one audit event.
- **I3** No secret (key plaintext, hash, pepper, JWT signing key) appears in any admin response or log.
- **I4** A hidden article is absent from public API responses within 60 s.
- **I5** A disabled channel returns 404 on all public surfaces.

## 8. Error model

`401 unauthorized`/`session-expired` · `403 csrf-invalid`/`forbidden` · `404 not-found` · `409 conflict` (duplicate source/pin, lock held) · `422 validation` (theme/contrast/fields) · `429 rate-limited` (login).

## 9. Observability

`admin_auth_total{result}`, `admin_mutations_total{action}`, `admin_refresh_total{status}`, `api_keys_active`. Logs: `admin.login`, `admin.mutation` (action/entity/id, no payload), `admin.logout`. Alerts on >5 failed logins/min.

## 10. Security

Threat model T1-T3, T7, T9. Argon2id; JWT HS256 with a 32-byte secret; httpOnly+Secure+SameSite=Strict; CSRF double-submit; login rate limit; no CORS; audit; session denylist. Admin UI is same-origin under the web app (or a protected `/admin` route with no indexing).

## 11. i18n

Console UI follows the operator's locale (en/es) via the same catalogs; audit payloads are language-neutral. Public effect (hidden/pin) is locale-independent.
