# Industry Sites (landing pages + news UI) - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 004/007/009 · **Owner:** engineering + design
**Needs:** owner ratification of ADR 004/007/009; otherwise nothing.

**ADRs referenced:** 004 (frontend), 007 (i18n), 009 (theming), 006 (channels)
**Related plans:** `.work/plans/20261105-personas-v1.md`, `.work/plans/foundation/20261105-03-product-adjacency-phased-modules.md`

## 1. Purpose

Render each industry as a distinct, professional, single-theme news site: fast, accessible, crawlable, bilingual, and recognizably suited to its profession - without forking the app per vertical.

## 2. In scope / Out of scope

**In:** channel home (splash + topic rail + story columns), article detail, about, contact, search, locale negotiation + switch, per-channel theming, disclaimers, SEO metadata/JSON-LD/sitemap, empty/error/loading states, a11y, performance budgets.
**Out:** user accounts, comments, newsletter signup (Phase B), e-commerce, native apps, editor UI (separate SPEC).

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Channel home** | `/{locale}/{industry}` - hero + splash + columns |
| **Locale** | `en` or `es`; negotiated on first visit, switchable |
| **Theme tokens** | Colors/typography/shape resolved from `industries.theme` to CSS variables |
| **Layout variant** | `editorial`, `professional`, or `academic` composition |
| **Disclaimer** | Per-channel, per-locale legal/professional notice |

## 4. Behavioural spec (rules)

**R1. Routing.** Public routes: `/{locale}/{industry}`, `/{locale}/{industry}/article/{id}`, `/{locale}/{industry}/about`, `/{locale}/{industry}/contact`, `/{locale}/{industry}/search`, `/{locale}` (default industry), `/` (negotiate → redirect). `locale` and `industry` are validated against enabled values; unknown values → `404` (locale) or `404` (industry). No locale-less deep links.

**R2. Locale negotiation.** On a request without `sn_locale` cookie: parse `Accept-Language` in order, pick the first supported tag, else `en`; 302 redirect to `/{locale}` preserving the rest of the path. With a cookie, the cookie wins. The switch control sets `sn_locale` (1 year, `SameSite=Lax`, `Secure`) and redirects to the same page in the target locale.

**R3. Language completeness.** Every user-visible string comes from `messages/{locale}.json`. CI fails if `es` is missing a key present in `en`. Article content: show `summary` when `summary_language == locale`; otherwise show the available-language notice and the summary in its own language with a label - never silently mix languages in one paragraph.

**R4. Channel theming.** Server-resolve `industries.theme` → CSS custom properties on `<html>` (`--sn-bg`, `--sn-surface`, `--sn-text`, `--sn-muted`, `--sn-primary`, `--sn-accent`, `--sn-border`, `--sn-radius`, `--sn-font-heading`, `--sn-font-body`). Components consume tokens only; no hardcoded colors. Unknown theme values fall back to the channel's layout variant defaults.

**R5. Layout variants.** `editorial` (serif headings, generous spacing - legal/health), `professional` (dense, data-forward - financial/logistics), `academic` (structured, calm - education). Variant is chosen by channel config, never by slug branching in components.

**R6. Contrast guardrail.** Every enabled channel theme passes WCAG AA contrast for text/background and primary/background pairs; CI validates the theme JSON and fails on violation. Max 2 font families per theme.

**R7. SEO.** Each page emits: unique `<title>`/description, canonical URL (`https://{host}/{locale}/{industry}/...`), `hreflang` alternates for all enabled locales + `x-default`, OpenGraph/Twitter tags, and JSON-LD (`ItemList` on home, `NewsArticle` on detail). `/sitemap.xml` is a sitemap index per channel/locale; `/robots.txt` disallows `/api/` and admin paths.

**R8. Rendering safety.** All feed-derived text is rendered as text (React escaping); no `dangerouslySetInnerHTML` without a sanitizer and a code comment. CSP: `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (theme variables), `img-src 'self' data: https:`, `frame-ancestors 'none'`.

**R9. Performance.** Home and article pages are server components with ISR (`revalidate=60` home, `300` article). No client data fetching for first paint. Images use `next/image` with dimensions; fonts are `next/font` with `display=swap`. Budgets: LCP p75 < 2.0 s, CLS < 0.1, INP < 200 ms, JS ≤ 120 KB gzip on home.

**R10. States.** Every list page defines **loading** (skeleton), **empty** ("no stories yet" + channel context), and **error** (retry + contact link) states. No blank page on API failure; the page renders a degraded shell with a visible notice.

**R11. Disclaimers and professional posture.** Each channel shows its localized disclaimer in the footer and on article pages: legal ("news, not legal advice"), financial ("news, not investment advice"), health ("news, not medical advice"), education/logistics as configured. Disclaimers are content (JSONB), not hardcoded JSX.

**R12. Contact form.** `POST /v1/contact` with name, email, optional phone, message, locale, honeypot. Client + server validation; 3 submissions/hour/IP; success state without revealing spam logic; failure state with a retry path and the channel email. Never echo back PII in the URL.

**R13. Accessibility.** WCAG 2.2 AA: semantic landmarks, skip link, visible focus, keyboard-operable locale switch and search, `aria-live` for async form states, `prefers-reduced-motion` respected, alt text on all images, form labels + error associations.

**R14. Navigation.** Top nav: Home, About, News (anchor/section), Contact, search, locale switch. Footer: channel name, disclaimer, privacy, terms, sitemap, contact email. Mirrors the reference site's information architecture (doc 02 I7).

**R15. Client integration parity.** The page data comes from `/v1` (server-side), using the same DTOs a third-party client would receive; no private database access from the web app. A change to a public DTO is a breaking change for this SPEC too.

## 5. Data model

Reads public API DTOs: `Industry`, `ArticleCard`, `ArticleDetail`, `Splash`, `Topic`, `Source`. No direct DB access. Locale state lives in a cookie; theme comes from the API response.

## 6. APIs

Consumes `/v1/industries`, `/v1/industries/{slug}`, `/v1/news`, `/v1/news/{id}`, `/v1/news/splash`, `/v1/topics`, `/v1/sources`, `/v1/contact`. Server-side fetch with `next: { revalidate }` and a 3 s timeout; on timeout, render the degraded shell (R10).

## 7. Invariants

- **I1** No page renders content from a channel other than the URL's `industry`.
- **I2** Every user-visible string exists in both locale catalogs (CI-enforced).
- **I3** No hardcoded color/font in a component; all visual values come from tokens.
- **I4** Every page has a canonical URL + `hreflang` set.
- **I5** A missing API response never produces a blank page or an unhandled error boundary.

## 8. Error model

`404` unknown locale/industry/article (friendly page + channel nav) · `503` upstream API unavailable (degraded shell + retry) · `400` invalid contact payload (inline field errors) · `429` contact rate limit (message, no internals).

## 9. Observability

Web-side: `web_page_render_duration_seconds{route}`, `web_api_fetch_total{endpoint,status}`, `web_client_errors_total`. Server logs include `request_id`, route, locale, industry, status. Real-user metrics via the platform's analytics choice (U9) or Lighthouse CI in the pipeline.

## 10. Security

Threat model T4 (XSS), T9 (CSRF for admin, not public), T10 (error leakage). CSP + escaping + sanitization; no secrets in the browser bundle; contact form honeypot + rate limit; no third-party scripts without owner approval.

## 11. i18n

See R2/R3 + ADR 007. Dates via `Intl.DateTimeFormat` in the channel timezone (default `America/El_Salvador`); numbers via `Intl.NumberFormat`. Locale switch preserves the current path. `x-default` points at `en`.
