# Industry Sites (landing pages + news UI) - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 004/007/009 · **Owner:** engineering + design
**Needs:** owner ratification of ADR 004/007/009; otherwise nothing.

**ADRs referenced:** 004 (frontend), 006 (channels), 007 (i18n), 009 (theming), 010 (refresh)
**Related plans:** `.work/plans/20261105-personas-v1.md`, `.work/plans/foundation/20261105-03-product-adjacency-phased-modules.md`

## 1. Purpose

Render each industry as a distinct, professional, single-theme news site: fast, accessible, crawlable, bilingual, and recognizably suited to its profession - without forking the app per vertical.

## 2. In scope / Out of scope

**In:** channel home (splash + topic rail + story columns), article detail, about, contact, search, lead CTA + lead form, locale negotiation + switch, per-channel theming, disclaimers, SEO metadata/JSON-LD/sitemap, empty/error/loading states, a11y, performance budgets, ISR + on-refresh revalidation.
**Out:** user accounts, comments, newsletter signup (Phase B), e-commerce, native apps, editor UI (separate SPEC), content translation.

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Channel home** | EN `/{industry}`, ES `/es/{industry}` - hero + splash + columns |
| **Locale** | `en` (unprefixed) or `es` (`/es`) |
| **Language bundle** | The single-language article set returned by `/v1` for this route |
| **Theme tokens** | Colors/typography/shape resolved from `industries.theme` to CSS variables |
| **Layout variant** | `editorial`, `professional`, or `academic` composition |
| **Disclaimer** | Per-channel, per-locale legal/professional notice |
| **Fallback** | API returned another language's bundle because the requested one is missing |

## 4. Behavioural spec (rules)

**R1. Routing.** Public routes: `/{industry}`, `/{industry}/article/{id}`, `/{industry}/about`, `/{industry}/contact`, `/{industry}/search` (English, unprefixed); the same paths under `/es/...`; `/` negotiates to the default industry; `/en/...` returns `308` to the unprefixed path. Locale codes are reserved and MUST NOT collide with industry slugs. Unknown industry → `404`; unknown locale prefix → `404`.

**R2. Locale negotiation.** Resolve in order: explicit prefix → `sn_locale` cookie → `Accept-Language` (first supported tag) → `en`. Without a cookie, a Spanish browser hitting `/{industry}` gets a `302` to `/es/{industry}`; an English browser stays on the clean URL via an internal rewrite to the `[locale]=en` tree. The switch sets `sn_locale` (1 year, `SameSite=Lax`, `Secure`) and hard-navigates to the same path with the prefix added/removed. Query strings and hash are preserved; every redirect re-attaches the prefix.

**R3. Language completeness and fallback.** Every user-visible UI string comes from `messages/{locale}.json`; CI fails if `es` misses a key present in `en`. The page's content language is the API bundle's `language`, which is authoritative:
- bundle matches the route locale → render normally;
- bundle `language` differs (missing bundle) → render the bundle **and** a visible "not yet available in Spanish" notice linking to the English page;
- bundle empty (exists but no items) → Spanish empty state, never English content under Spanish chrome.
The UI never mixes languages in one paragraph.

**R4. Channel theming.** Server-resolve `industries.theme` → CSS custom properties on `<html>` (`--sn-bg`, `--sn-surface`, `--sn-text`, `--sn-muted`, `--sn-primary`, `--sn-accent`, `--sn-border`, `--sn-radius`, `--sn-font-heading`, `--sn-font-body`). Components consume tokens only; no hardcoded colors. Unknown theme values fall back to the layout variant defaults.

**R5. Layout variants.** `editorial` (serif headings, generous spacing - legal/health), `professional` (dense, data-forward - financial/logistics), `academic` (structured, calm - education). Variant is chosen by channel config, never by slug branching in components.

**R6. Contrast guardrail.** Every enabled channel theme passes WCAG AA contrast for text/background and primary/background pairs; CI validates the theme JSON and fails on violation. Max 2 font families per theme.

**R7. SEO.** Each page emits: unique `<title>`/description, canonical (`https://{host}/{industry}/...` for EN, `/es/{industry}/...` for ES), `hreflang` alternates for all enabled locales + `x-default` (English), OpenGraph/Twitter tags with per-locale `og:locale`, and JSON-LD (`ItemList` on home, `NewsArticle` on detail). `/sitemap.xml` is a sitemap index per channel/locale with alternates; `/robots.txt` disallows `/api/` and admin paths. Metadata is locale-aware via `generateMetadata` (never a static English export).

**R8. Rendering safety.** All feed-derived text is rendered as text (React escaping); no `dangerouslySetInnerHTML` without a sanitizer and a code comment. CSP: `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (theme variables), `img-src 'self' data: https:`, `frame-ancestors 'none'`.

**R9. Performance and freshness.** Home and article pages are server components with ISR: home `revalidate=60`, article `revalidate=300`; a successful refresh run triggers on-demand revalidation of the affected channel routes. No client data fetching for first paint. Images use `next/image` with dimensions; fonts are `next/font` with `display=swap`. Budgets: LCP p75 < 2.0 s, CLS < 0.1, INP < 200 ms, JS ≤ 120 KB gzip on home.

**R10. States.** Every list page defines **loading** (skeleton), **empty** ("no stories yet" + channel context), **fallback** (other-language notice), and **error** (retry + contact link) states. No blank page on API failure; the page renders a degraded shell with a visible notice.

**R11. Disclaimers and professional posture.** Each channel shows its localized disclaimer in the footer and on article pages: legal ("news, not legal advice"), financial ("news, not investment advice"), health ("news, not medical advice"), education/logistics as configured. Disclaimers are content (JSONB), not hardcoded JSX.

**R12. Contact form.** `POST /v1/contact` with name, email, optional phone, message, locale, honeypot. Client + server validation; 3 submissions/hour/IP; success state without revealing spam logic; failure state with a retry path and the channel email. Never echo back PII in the URL.

**R13. Accessibility.** WCAG 2.2 AA: semantic landmarks, skip link, visible focus, keyboard-operable locale switch and search, `aria-live` for async form states, `prefers-reduced-motion` respected, alt text on all images, form labels + error associations.

**R14. Navigation.** Top nav: Home, About, News (anchor/section), Contact, search, locale switch. Footer: channel name, disclaimer, privacy, terms, sitemap, contact email. Mirrors the reference site's information architecture (doc 02 I7).

**R15. Client integration parity.** The page consumes the public API only - `/v1/news/bundle` for the channel home (splash/columns/topics/sources/desk brief) and `/v1/news/{id}` for detail - server-side. No private database access from the web app. A public DTO change is a breaking change for this SPEC too.

**R16. CTA placement (lead generation).** Every channel home shows one primary CTA above the fold: a hero card plus a sticky mobile bar that appears after 60% scroll and is dismissible. Articles show the CTA after the summary and at end of article, never mid-paragraph. Search/about show a compact block; the footer carries a quiet link. One primary CTA per page; secondary (brief signup) never competes visually. Placement and offer come from channel config (JSONB), not hardcoded JSX.

**R17. Lead form.** `LeadForm` posts to `POST /v1/leads` with name, email, phone (optional except logistics), company (logistics), need/message, channel-specific select, and explicit consent. Honeypot field; 5 submissions/hour/IP; duplicate submission within 10 minutes is dropped silently (200). Success replaces the form with a confirmation and response expectation; no PII is echoed or placed in the URL. Failure shows field-level errors and a retry path.

**R18. Consent, disclaimers, and ethics.** Consent is unchecked by default, names the purpose, links the privacy policy, and stores the consent text version + timestamp. The channel disclaimer appears beside the CTA (legal: attorney advertising / not legal advice; financial: not investment advice / risk; health: not medical advice / emergency line; education and logistics per config). Banned: fake urgency, pre-checked consent, guaranteed outcomes, exit-intent traps.

**R19. Funnel instrumentation.** Emit `cta_impression`, `cta_click`, `lead_form_start`, and `lead_submit{result}` with channel, placement, and locale only - no name, email, or phone. Attribution (`utm`, referrer, landing path, article id) is captured server-side on the lead record, not in analytics payloads.

## 5. Data model

Reads public API DTOs: `Industry`, `Bundle` (`splash`, `columns`, `items`, `topics`, `sources`, `featured`, `ai_summary`, `language`, `fallback`), `ArticleCard`, `ArticleDetail`, `Topic`, `Source`, `CtaConfig`. No direct DB access. Locale state lives in a cookie; theme comes from the API response; lead submissions go to `/v1/leads`.

## 6. APIs

Consumes `/v1/industries`, `/v1/industries/{slug}`, `/v1/news/bundle`, `/v1/news`, `/v1/news/{id}`, `/v1/topics`, `/v1/sources`, `/v1/contact`, `/v1/leads`. Server-side fetch with `next: { revalidate }` and a 3 s timeout; on timeout, render the degraded shell (R10). The bundle endpoint is the reference-compatible contract (news-api R16).

## 7. Invariants

- **I1** No page renders content from a channel other than the URL's `industry`.
- **I2** Every user-visible string exists in both locale catalogs (CI-enforced).
- **I3** No hardcoded color/font in a component; all visual values come from tokens.
- **I4** Every page has a canonical URL + `hreflang` set (English unprefixed, Spanish `/es`).
- **I5** A missing API response never produces a blank page or an unhandled error boundary.
- **I6** A page never mixes languages: the rendered content language equals the bundle `language`, and a difference is visibly labeled.
- **I7** Every public page has exactly one primary CTA; the lead form never submits without explicit consent.

## 8. Error model

`404` unknown locale/industry/article (friendly page + channel nav) · `503` upstream API unavailable (degraded shell + retry) · `400` invalid contact payload (inline field errors) · `429` contact rate limit (message, no internals).

## 9. Observability

Web-side: `web_page_render_duration_seconds{route}`, `web_api_fetch_total{endpoint,status,language}`, `web_client_errors_total`, `web_fallback_rendered_total{route}`. Server logs include `request_id`, route, locale, industry, status. Real-user metrics via the platform's analytics choice (U9) or Lighthouse CI in the pipeline.

## 10. Security

Threat model T4 (XSS), T9 (CSRF for admin, not public), T10 (error leakage). CSP + escaping + sanitization; no secrets in the browser bundle; contact form honeypot + rate limit; no third-party scripts without owner approval.

## 11. i18n

See R2/R3 + ADR 007. UI catalogs EN/ES typed; dates via `Intl` per-locale map (`en-US`, `es-ES`) in the channel timezone (default `America/El_Salvador`); numbers via `Intl.NumberFormat`. Locale switch preserves the current path. `x-default` points at the English URL. Topic labels are localized from the API.
