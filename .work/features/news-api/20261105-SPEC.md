# Public News API - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 008 · **Owner:** engineering
**Needs:** owner ratification of ADR 008; otherwise nothing.

**ADRs referenced:** 006 (tenancy), 008 (API contract), 011 (auth), 012 (release)
**Related plans:** `.work/plans/foundation/20261105-04-foundation-architecture.md`, `.work/standards/20261105-api-style-guide.md`

## 1. Purpose

Give any client site - LogicBison first, third parties later - a reliable, cacheable, versioned contract for industry news: channels, article lists/detail, featured splash, topics, sources, and search. The API is the product boundary; the website is one consumer of it.

## 2. In scope / Out of scope

**In:** public read endpoints under `/v1`, cursor pagination, ETag/304, locale-aware content, optional API keys, rate limits, OpenAPI + docs, admin auth and mutations needed to operate the read API.
**Out:** user accounts, write endpoints for end users, webhooks (Phase B), GraphQL, bulk export (Phase B), payments.

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Channel / industry** | A themed news vertical (`legal`, `financial`, ...) identified by `slug` |
| **Article** | A normalized news item: title, canonical URL, publisher, summary, topics, score |
| **Splash** | Lead article + favorites used by the hero area |
| **Locale** | BCP 47 language tag (`en`, `es`) |
| **Cursor** | Opaque pagination token encoding `(score, published_at, id)` |
| **Bundle** | A cached response body keyed by `(industry, locale, query, cursor)` |

## 4. Behavioural spec (rules)

**R1. Channel listing.** `GET /v1/industries` returns every `enabled` channel ordered by `sort_order, slug`, each with `slug`, `name`, `code`, `locales`, and a `theme_summary` (primary/accent colors, layout variant). Disabled channels are omitted.

**R2. Channel detail.** `GET /v1/industries/{slug}` returns the full public channel object incl. localized name/tagline, disclaimer text, and available locales. Unknown slug → `404`. Disabled → `404` (not `403`; no existence leak).

**R3. News list.** `GET /v1/news?industry={slug}&locale={tag}` returns published articles for exactly one channel, newest-and-highest-score first, with `id`, `title`, `summary` (nullable), `url`, `publisher`, `published_at`, `topics`, `language`, `verification`. Default `limit=20`, max 50.

**R4. Channel isolation (invariant).** Every read MUST filter `industry_id = <resolved channel>`; a response MUST NOT contain an article, source, or topic belonging to another channel. Omitting `industry` is an error (`400`) unless exactly one channel is enabled. No endpoint returns cross-channel results.

**R5. Visibility window.** Only `status = published` and `published_at >= now() - retention_days` (default 7) are returned. `hidden` articles, expired articles, and items from disabled sources are never returned, including from cache.

**R6. Article detail.** `GET /v1/news/{id}` returns the full card: title, summary, publisher, canonical URL, published_at, topics, language, corroboration, `verification`, and `related` (up to 3 same-channel items). Hidden/expired/unknown → `404`.

**R7. Splash.** `GET /v1/news/splash?industry=&locale=` returns `lead` (exactly 1 when any item exists) and `favorites` (up to 3), each a card object, plus `generated_at`. With zero items, `lead` is `null` and `favorites` is `[]` (valid 200, never 404).

**R8. Pagination and filtering.** Cursor pagination only; `limit` bounded 1-50; `topic` filters by topic slug; `q` performs full-text search over title+summary (`websearch_to_tsquery`), 3-64 chars. Unknown params → `400`. Sorting is deterministic: `score DESC, published_at DESC, id DESC`.

**R9. Rate limiting and abuse.** Keyless requests are limited to 120 req/min per IP; keyed to 600 req/min per key. Exceeding returns `429` with `Retry-After` and `RateLimit-*` headers. `q` length and cursor size are capped. Response bodies are never unbounded.

**R10. Caching.** Public responses carry a weak `ETag` and `Cache-Control: public, max-age=60, stale-while-revalidate=300`. `If-None-Match` matching returns `304` with no body. Cache keys include channel, locale, normalized query, and cursor. Admin responses are `no-store`.

**R11. Authentication and keys.** Public reads need no credential; a valid `X-API-Key` raises the quota. Keys are 32 random bytes prefixed `sn_live_`, shown once, stored as `sha256(pepper || key)`, compared in constant time, with `scopes`, `enabled`, `last_used_at`. Invalid/revoked key → `401`; insufficient scope → `403`. Admin endpoints require a `Bearer` JWT (15 min, HS256, `jti`), and every mutation writes an audit event.

**R12. Admin mutations.** `POST /v1/admin/refresh`, source CRUD, pins, hide, and key CRUD require admin auth + CSRF double-submit (`X-CSRF-Token` = `sn_csrf` cookie). Mutations are idempotent where the verb allows (`Idempotency-Key` honored for refresh). No mutation is exposed without auth.

**R13. Localization.** Requests accept `locale` (default `en`). Responses include `meta.locale` and per-item `language`. When a summary is unavailable in the requested locale, the item is returned with `summary: null` and `summary_available_locales: ["en"]` - never a mixed-language body. Dates are ISO-8601 UTC.

**R14. Error contract.** All errors are RFC 7807 objects with `type`, `title`, `status`, `detail`, `instance`, `request_id`. No stack traces, SQL, or upstream bodies. `X-Request-Id` is always echoed.

**R15. Contract stability.** Within `v1`, changes are additive only (new optional fields/endpoints). Removing/renaming a field, changing a type, or changing default ordering requires `v2` + 6-month overlap + `Sunset` header. The committed OpenAPI snapshot `docs/api/openapi.v1.json` is regenerated in CI and diffed in PRs.

## 5. Data model

Reads `industries`, `industry_locales`, `sources`, `articles`, `topics`, `article_topics`, `pins`, `api_keys`, `audit_events` (doc 04 §4). No new tables in this SPEC; indexes required:

| Index | Purpose |
|-------|---------|
| `articles (industry_id, status, published_at DESC)` | R3/R5 |
| `articles (industry_id, score DESC, published_at DESC, id)` | R8 ordering |
| `articles USING gin(search_vector)` | R8 search |
| `article_topics (topic_id, article_id)` | topic filter |
| `api_keys (key_hash)` UNIQUE | R11 |

See `.work/standards/20261105-api-style-guide.md` §4 for the endpoint table. This SPEC binds: `/v1/industries`, `/v1/industries/{slug}`, `/v1/news`, `/v1/news/{id}`, `/v1/news/splash`, `/v1/topics`, `/v1/sources`, `/v1/contact`, `/v1/admin/*`, `/v1/health`, `/v1/openapi.json`, `/v1/docs`.

## 7. Invariants

- **I1** Every response item belongs to the requested channel (R4).
- **I2** No hidden/expired article is served, even from a warm cache (R5, R10).
- **I3** `limit` never exceeds 50; total response size < 1 MB.
- **I4** Every response has `meta.request_id`; every error has `type` + `status`.
- **I5** A `304` body is empty and its headers match the prior `200`.
- **I6** No secret, hash, or internal score appears in a public payload.

## 8. Error model

`400 invalid-query` · `400 invalid-cursor` · `401 invalid-key`/`unauthorized` · `403 insufficient-scope` · `404 not-found` · `409 conflict` · `422 validation` · `429 rate-limited` · `502 upstream-error` · `503 dependency-unavailable`.

## 9. Observability

`http_requests_total`, `http_request_duration_seconds`, `rate_limited_total`, `cache_hits_total`, `news_reads_total{industry,endpoint}`, `contact_submissions_total`. Log `request.end` with route/status/duration/request_id; never log query strings containing `q` (may contain personal text).

## 10. Security

Threat model T4 (XSS via payload), T7 (key elevation), T8 (DoS), T9 (CSRF), T10 (error leakage). Rate limits in Redis; keys hashed; CSP on docs page; no wildcard CORS (public read supports `Access-Control-Allow-Origin: *` only for `GET` without credentials).

## 11. i18n

`locale` query + `Accept-Language` fallback; `meta.locale`; localized channel names; `summary_available_locales`. Adding a locale requires no API change (text columns + catalogs).
