# Public News API - Feature SPEC

**Status:** Draft (2026-11-05) - pending owner ratification of ADR 007/008 · **Owner:** engineering
**Needs:** owner ratification of ADR 007/008; otherwise nothing.

**ADRs referenced:** 006 (tenancy), 007 (i18n), 008 (API contract), 010 (refresh), 011 (auth), 012 (release)
**Related plans:** `.work/plans/foundation/20261105-04-foundation-architecture.md`, `.work/standards/20261105-api-style-guide.md`

## 1. Purpose

Give any client site - LogicBison first, third parties later - a reliable, cacheable, versioned contract for industry news: channels, per-language bundles, article lists/detail, featured splash, topics, sources, search, and an explicit on-demand refresh. The API is the product boundary; the website is one consumer of it.

## 2. In scope / Out of scope

**In:** public read endpoints under `/v1`, cursor pagination, a reference-compatible bundle endpoint, ETag/304, locale/language selection, optional API keys, rate limits, OpenAPI + docs, admin auth and the mutations needed to operate the read API (refresh, force-poll).
**Out:** user accounts, write endpoints for end users, webhooks (Phase B), GraphQL, bulk export (Phase B), payments, translation of content.

## 3. Domain language

| Term | Meaning |
|------|---------|
| **Channel / industry** | A themed news vertical (`legal`, `financial`, ...) identified by `slug` |
| **Article** | A normalized news item: title, canonical URL, publisher, summary, topics, score, `language` |
| **Language** | The article's source language (`en`, `es`); assigned at ingest and immutable |
| **Bundle** | One language's processed feed for one channel: splash, columns, items, topics, sources, featured, desk brief |
| **Splash** | Lead article + favorites used by the hero area |
| **Cursor** | Opaque pagination token encoding `(score, published_at, id)` |
| **Locale** | Requested presentation language; selects the bundle |

## 4. Behavioural spec (rules)

**R1. Channel listing.** `GET /v1/industries` returns every `enabled` channel ordered by `sort_order, slug`, each with `slug`, `name`, `code`, `locales`, and a `theme_summary` (primary/accent colors, layout variant). Disabled channels are omitted.

**R2. Channel detail.** `GET /v1/industries/{slug}` returns the full public channel object incl. localized name/tagline, disclaimer text, and available locales. Unknown slug → `404`. Disabled → `404` (not `403`; no existence leak).

**R3. News list.** `GET /v1/news?industry={slug}&locale={tag}` returns published articles **whose `language` equals `locale`**, highest-score-first, with `id`, `title`, `summary` (nullable), `url`, `publisher`, `published_at`, `topics`, `language`, `verification`. Default `limit=20`, max 50. There is no mixed-language result set.

**R4. Channel isolation (invariant).** Every read MUST filter `industry_id = <resolved channel>`; a response MUST NOT contain an article, source, or topic belonging to another channel. Omitting `industry` is an error (`400`) unless exactly one channel is enabled. No endpoint returns cross-channel results.

**R5. Visibility window.** Only `status = published` and `published_at >= now() - retention_days` (default 7) are returned. `hidden` articles, expired articles, and items from disabled sources are never returned, including from cache.

**R6. Article detail.** `GET /v1/news/{id}` returns the full card: title, summary, publisher, canonical URL, published_at, topics, `language`, corroboration, `verification`, and `related` (up to 3 same-channel **same-language** items). Hidden/expired/unknown → `404`.

**R7. Splash.** `GET /v1/news/splash?industry=&locale=` returns `lead` (exactly 1 when the language bundle has items) and `favorites` (up to 3), each a card object, plus `generated_at`. With zero items, `lead` is `null` and `favorites` is `[]` (valid 200, never 404).

**R8. Pagination and filtering.** Cursor pagination only; `limit` bounded 1-50; `topic` filters by topic slug; `q` performs full-text search over title+summary (`websearch_to_tsquery`), 3-64 chars. Unknown params → `400`. Sorting is deterministic: `score DESC, published_at DESC, id DESC`.

**R9. Rate limiting and abuse.** Keyless requests are limited to 120 req/min per IP; keyed to 600 req/min per key. Exceeding returns `429` with `Retry-After` and `RateLimit-*` headers. `q` length and cursor size are capped. Response bodies are never unbounded.

**R10. Caching.** Public responses carry a weak `ETag` and `Cache-Control: public, max-age=60, stale-while-revalidate=300`. `If-None-Match` matching returns `304` with no body. Cache keys include channel, language/locale, normalized query, and cursor. Admin responses are `no-store`.

**R11. Authentication and keys.** Public reads need no credential; a valid `X-API-Key` raises the quota. Keys are 32 random bytes prefixed `sn_live_`, shown once, stored as `sha256(pepper || key)`, compared in constant time, with `scopes`, `enabled`, `last_used_at`. Invalid/revoked key → `401`; insufficient scope → `403`. Admin endpoints require a `Bearer` JWT (15 min, HS256, `jti`), and every mutation writes an audit event.

**R12. Admin mutations.** `POST /v1/admin/refresh`, source CRUD, pins, hide, and key CRUD require admin auth + CSRF double-submit (`X-CSRF-Token` = `sn_csrf` cookie). Mutations are idempotent where the verb allows (`Idempotency-Key` honored for refresh). No mutation is exposed without auth.

**R13. Localization and fallback.** `locale` selects the language bundle (default `en`). Responses include `meta.locale`, `meta.language` (authoritative), and per-item `language`. Semantics per ADR 007 §3:

| State | Response |
|-------|----------|
| Bundle exists with items | `language = locale`, `meta.fallback = false` |
| Bundle exists but empty | `language = locale`, empty data, `meta.fallback = false` (honest empty) |
| Bundle missing | `en` bundle, `language = "en"`, `meta.fallback = true` |
| Unsupported locale | `400 invalid-locale` |

Article text is never translated; a client MUST NOT assume `summary` exists in the requested language.

**R14. Error contract.** All errors are RFC 7807 objects with `type`, `title`, `status`, `detail`, `instance`, `request_id`. No stack traces, SQL, or upstream bodies. `X-Request-Id` is always echoed.

**R15. Contract stability.** Within `v1`, changes are additive only (new optional fields/endpoints). Removing/renaming a field, changing a type, or changing default ordering requires `v2` + 6-month overlap + `Sunset` header. The committed OpenAPI snapshot `docs/api/openapi.v1.json` is regenerated in CI and diffed in PRs.

**R16. Bundle endpoint (reference-compatible).** `GET /v1/news/bundle?industry=&locale=` returns one language bundle for one channel: `generated_at`, `language`, `fallback`, `total`, `splash`, `columns`, `items` (flat display order), `topics`, `sources`, `featured` (`lead`, `favorites`), `ai_summary` (nullable), `retention_max_age_days`. This is the migration target for LogicBison's `GET /api/news?lang=` client. Layout: top `max_items` by score; `splash` = first `splash_count`; remaining dealt round-robin into `column_count` columns, `per_column` each. Empty bundle → 200 with empty arrays (never 404). Missing bundle → EN fallback per R13.

**R17. On-demand refresh (admin).** `POST /v1/admin/refresh` accepts `{industry, force}` and returns `202` + `run_id`; `force=true` bypasses the schedule but not the single-flight lock. If a run is active, return `409` with the active `run_id`. `GET /v1/admin/refresh/{run_id}` returns `{status, started_at, finished_at, stats}`. This is the only API path that triggers ingestion; public reads never do. Idempotency-Key is honored for 24 h.

**R18. Lead capture (public).** `POST /v1/leads` accepts `{industry, kind: consultation|brief, name, email, phone?, company?, message?, locale, consent, source_page?, article_id?, utm?}`. Returns `201 {id}` only (no PII echo). `consent` must be true; the current consent-text version is stored. Honeypot + duplicate suppression (10 min) + 5/hour/IP. `422` on validation, `429` with `Retry-After` on rate limit. No lead PII appears in any public response, log line, or analytics event.

**R19. Lead administration.** Admin only: `GET /v1/admin/leads` (filter industry/status), `PATCH /v1/admin/leads/{id}` (status), `POST /v1/admin/leads/{id}/assign`, `GET|POST|PATCH /v1/admin/partners`, `GET /v1/admin/leads/{id}/export`, `DELETE /v1/admin/leads/{id}` (DSAR). Every mutation writes `lead_events` and an audit event. No cross-channel visibility.

**R21. Industry-channel creation (additive v1).** Admin-only
`POST /v1/admin/industries` creates a data-only channel: slug, code, name, theme,
locale copies, disclaimers, CTA, timezone, retention, sort order, enabled, and
optional topics. Theme validation (tokens, contrast, layout, font count) applies;
duplicate slug → `409`; reserved slugs and unsupported locales → `422`. No code
deploy is needed for the new public routes or `/v1` reads.

**R20. Lead privacy and retention.** Lead records are `Confidential` (data-classification §3), retained 24 months; spam/rejected 90 days; deleted on request within 30 days. `ip_hash`/`ua_hash` are peppered SHA-256, never raw. CTA funnel events contain no PII and are retained 90 days.

## 5. Data model

Reads `industries`, `industry_locales`, `sources`, `articles`, `topics`, `article_topics`, `pins`, `api_keys`, `audit_events`, `refresh_runs` (doc 04 §4). No new tables in this SPEC; indexes required:

| Index | Purpose |
|-------|---------|
| `articles (industry_id, language, status, published_at DESC)` | R3/R5/R16 |
| `articles (industry_id, language, score DESC, published_at DESC, id)` | R8/R16 ordering |
| `articles USING gin(search_vector)` | R8 search |
| `article_topics (topic_id, article_id)` | topic filter |
| `api_keys (key_hash)` UNIQUE | R11 |
| `refresh_runs (industry_id, started_at DESC)` | R17 |

## 7. Invariants

- **I1** Every response item belongs to the requested channel (R4).
- **I2** No hidden/expired article is served, even from a warm cache (R5, R10).
- **I3** `limit` never exceeds 50; total response size < 1 MB.
- **I4** Every response has `meta.request_id`; every error has `type` + `status`.
- **I5** A `304` body is empty and its headers match the prior `200`.
- **I6** No secret, hash, or internal score appears in a public payload.
- **I7** Every item in a response has `language` equal to `meta.language` (no mixed-language bundle).

## 8. Error model

`400 invalid-query` · `400 invalid-cursor` · `400 invalid-locale` · `401 invalid-key`/`unauthorized` · `403 insufficient-scope` · `404 not-found` · `409 refresh-in-progress` · `422 validation`/`consent-required` · `429 rate-limited` · `502 upstream-error` · `503 dependency-unavailable`.

## 9. Observability

`http_requests_total`, `http_request_duration_seconds`, `rate_limited_total`, `cache_hits_total`, `news_reads_total{industry,endpoint,language}`, `contact_submissions_total`, `refresh_manual_total{industry}`, `leads_total{industry,status}`, `leads_rate_limited_total`, `lead_route_latency_seconds`. Log `request.end` with route/status/duration/request_id; never log query strings containing `q` (may contain personal text).

## 10. Security

Threat model T4 (XSS via payload), T7 (key elevation), T8 (DoS), T9 (CSRF), T10 (error leakage). Rate limits in Redis; keys hashed; CSP on docs page; no wildcard CORS (public read supports `Access-Control-Allow-Origin: *` only for `GET` without credentials).

## 11. i18n

`locale` query + `Accept-Language` fallback; `meta.locale`, `meta.language`, `meta.fallback`; localized channel names and topic labels; per-item `language`. Adding a locale requires no API change (text columns + catalogs).
