# SPEC — source acquisition

**Status:** Implemented (2026-11-10) · **Needs:** nothing.
**Scope:** find candidates, prove what they add, record why we may read them, and show the traffic we send back.
**Builds on:** `fetch-safety` (permission), `source-availability` (refusals, credentials, ledger).

---

## 1. Problem

The portfolio grew by hand: an operator pasted a URL, a profile was edited, and nothing measured whether the new feed added stories the desk did not already carry. There was also no answer to the only question a publisher asks — "what do you send us?" — and no record of outreach.

## 2. Requirements

### R1 — Discovery is read-only and graded
`sources discover` accepts a URL list or an OPML export, and for each candidate returns permission, quality, novelty and fit. It never writes a source; the accepted rows come back as a `profile_snippet`.

*Accept:* plain list and OPML both parse; a configured feed is rejected with its state; a robots-refused feed is rejected before any fetch.

### R2 — Novelty is measured, not assumed
Exact-title overlap against the desk's last 30 days. `> 50 %` → `review` with the ratio in the reason; quality failure → `reject`.

*Accept:* unit tests for normalisation and ratio; a real feed with no desk overlap reports `0.0`.

### R3 — Licence is recorded
`sources.licence_type` (`unknown`/`public-domain`/`cc-by`/`cc-by-sa`/`syndication`/`licensed`/`proprietary`), settable from the deployment profile, shown in the admin row. Government feeds set to `public-domain`; the rest stay `unknown` until checked.

*Accept:* profile carries the value; re-apply is idempotent; admin row renders it.

### R4 — Outreach is tracked
`contacted_at` + `outreach_note`, written by `sources outreach`, shown in admin.

*Accept:* the command round-trips and an unknown id exits 2.

### R5 — Return traffic is countable
`GET /v1/outbound/{article_id}` increments `articles.outbound_clicks` and 302s to the publisher; `published` only; `Cache-Control: no-store`; no reader identifier. The web `/go/{id}` route proxies it so the reader stays on the desk's host until the redirect.

*Accept:* 302 + publisher URL, 404 for an unknown id, counter increments exactly once per request, e2e asserts the link is `/go/…` and that the route answers 302.

### R6 — Health is visible
`sources health` reports per-source `items_7d`, `items_30d`, `clicks_30d`, `consecutive_failures`, `permission_state`, and a `needs_attention` list (<10 items in 30 days or ≥5 failures). `sources report` shows the portfolio by desk: enabled count, languages, licences, permission.

*Accept:* both run against the dev database and return rows.

## 3. Data

Migration `018_source_acquisition.sql`: three columns on `sources`, one on `articles`
(`outbound_clicks`), one index on `(source_id, created_at)`. Additive, no backfill.

## 4. Decisions

1. **Discovery does not write.** Accepting a candidate is an editorial act; it belongs in a profile diff, not a CLI side effect.
2. **Overlap is exact-title, not embeddings.** Cheap, explainable, and conservative in the right direction (it over-counts novelty, so a `review` verdict is the safety net).
3. **Clicks are article-level integers.** No session, no IP, no cookie: enough to answer "how many readers did you send", nothing that becomes a tracking profile.
4. **No browser UA.** Retained from the availability SPEC; the acquisition answer to a refusal is outreach, not disguise.
