# Personas v1 - System News

**What it is:** the four personas the product serves, their jobs, and the acceptance bar for their primary journeys.
**Status:** Draft (2026-11-05) - inferred from the brief; owner validation needed (ASSUMPTIONS A14) · **Needs:** owner confirmation of persona 1 and 3.

---

## P1 - Industry reader (primary)

| Attribute | Detail |
|-----------|--------|
| Who | A professional in one of the five verticals (lawyer, advisor, clinician, educator, logistics manager), or an informed layperson following that sector |
| Goal | Skim what matters in their field in under 5 minutes, in their language, with trustworthy attribution |
| Pains | Noise, clickbait, paywalled teasers, mixed-language sites, slow pages, ads that block content |
| Context | Mobile-first, often between tasks; may be in a jurisdiction other than the publisher's |
| Primary journey | Land from search/social → home hero → scan splash + columns → open 1-3 articles → click through to the publisher |
| Success | Finds a relevant story within 10 s; understands why it matters from the summary; trusts the source label |
| Accessibility | Screen reader, keyboard, 200% zoom, reduced motion, high contrast |
| Frequency | Daily, 2-5 sessions/week |

**Design implications:** fast LCP, legible typography, clear recency and source labels, prominent language switch, no intrusive interstitials, disclaimer visible but not blocking.

## P2 - Editor / operator

| Attribute | Detail |
|-----------|--------|
| Who | 1-3 people running the network; may be non-technical |
| Goal | Keep each channel fresh and credible; fix a bad story fast; see pipeline health at a glance |
| Pains | Silent feed failures, bad AI summaries, no easy way to hide a story, opaque logs |
| Context | Desktop, short bursts, often on mobile for urgent hides |
| Primary journey | Login → health board → inspect failing source → test fetch → hide/pin a story → trigger refresh |
| Success | Can diagnose "channel is empty" in < 2 min; can hide a story in < 30 s |
| Accessibility | Keyboard, clear labels, no colour-only status |
| Frequency | Daily + on-call |

**Design implications:** status-first console, audit visibility, destructive actions confirmed, no raw SQL.

## P3 - Client developer / agentic assistant

| Attribute | Detail |
|-----------|--------|
| Who | A developer integrating a client site (LogicBison first), or an AI coding agent following docs |
| Goal | Get a working request in minutes; know the exact shapes, limits, and failure modes |
| Pains | Undocumented fields, surprise breaking changes, unclear caching, pagination ambiguity |
| Context | Reads OpenAPI + examples; copies curl; runs tests against a sandbox |
| Primary journey | Read quickstart → copy curl → integrate list/detail → handle 429/5xx → ship |
| Success | First successful call < 5 min; no support question needed for the core read path |
| Accessibility | n/a (docs must be machine-readable) |

**Design implications:** committed OpenAPI, copy-paste examples (curl/TS/Python), explicit error table, versioning promise, changelog, `agent-quickstart.md`.

## P4 - Site owner / operator-business

| Attribute | Detail |
|-----------|--------|
| Who | The person accountable for the network's growth, cost, and legal posture |
| Goal | Launch new industries cheaply, grow traffic, stay out of legal trouble, control cost |
| Pains | Per-vertical rebuilds, copyright risk, unpredictable AI/cloud bills |
| Primary journey | Decide channel → configure theme + sources → review disclaimers → launch → monitor cost/traffic |
| Success | New channel live in < 1 day without code changes; no copyright complaint unresolved > 24 h |
| Frequency | Weekly |

**Design implications:** channel-as-data, cost dashboards, takedown workflow, clear disclaimers per vertical.

## Journey acceptance (used by SPEC tests)

| Journey | Persona | Acceptance |
|---------|---------|------------|
| Read the top story in Spanish | P1 | LCP < 2.0 s; summary in Spanish; language switch one click |
| Diagnose an empty channel | P2 | Console shows failing source + last error + test action |
| Integrate the list endpoint | P3 | curl example returns 200 with documented envelope |
| Launch a sixth industry | P4 | Data-only change; no code deploy |
